## 二、核心表：unwarranted_material（未过保物料）

建表于 2026-08-01（migration-unwarranted-material.sql），当前结构：

| 字段 | 类型 | 说明 |
|---|---|---|
| id | BIGINT PK | 主键 |
| company_id | BIGINT | 公司 ID（默认 1） |
| record_date | DATE | 日期 |
| factory | VARCHAR(100) | 厂房 |
| machine_no | VARCHAR(100) | 机台号 |
| equip_repair_debugging | TEXT | 处理方式（原"设备维修调试"，显示名已改） |
| repair_material_on | VARCHAR(200) | 上机物料（原"维修物料装上"） |
| repair_person | VARCHAR(50) | 维修人 |
| warranty_status | VARCHAR(20) | 未过保（回填自维修记录是否过保） |
| part_name | VARCHAR(200) | 配件名称 |
| quantity | INT | 数量 |
| material_code | VARCHAR(100) | 料号（原"物料编码"） |
| unique_id | VARCHAR(255) | 唯一标识编号（厂房-机台号+配件名称） |
| last_date_no / current_date_no | VARCHAR(300) | 上次/本次日期+编号 |
| plant_machine | VARCHAR(255) | 厂房+机台号 |
| year_month | VARCHAR(20) | 年+月（FY2608 格式） |
| repair_amount | DECIMAL(12,2) | 维修金额（合约） |
| total_count / occurrence_no | INT | 总次数 / 第几次 |
| last_date / current_date | DATE | 上次日期 / 本次日期 |
| over_six_months | VARCHAR(10) | 超六个月（N/Y/1st） |
| usage_months | VARCHAR(20) | 使用时长/月 |
| last_repair_person | VARCHAR(50) | 上次维修人 |
| **original_record_id** | BIGINT | **关联维修记录 ID**（一个维修记录只允许关联一条；下推/同步/级联删除链路的核心字段） |
| **category** | VARCHAR(100) | 类别（按料号从物料表自动回填） |
| created_by / updated_by | VARCHAR(50) | 创建人/更新人 |
| created_at / updated_at | DATETIME | 创建/更新时间（updated_at 自动更新） |

索引：`idx_uw_unique(unique_id)`、`idx_uw_mcode(material_code)`、`idx_uw_date(record_date)`、`idx_uw_original(original_record_id)`、`idx_uw_company_ym_plant(company_id, year_month, plant_machine)`【本次新增】

## 三、数据看板相关

数据看板（2026-08-03 起）本身**零 DDL**——全部为对既有表的实时聚合查询：

- `unwarranted_material`：维修金额（GROUP BY plant_machine）、物料频次/返修频次（GROUP BY material_code）
- `original_record`：故障频次（GROUP BY 厂房-机台）、机台列表去重
- `base_material_156`：单价/类别/配件名称（行维度）

**本次性能优化（2026-08-04）**新增两条索引以加速上述聚合（`idx_uw_company_ym_plant`、`idx_or_company_ym`）。

⚠️ **注意**：实测 EXPLAIN 显示当前数据量（unwarranted_material 约 4.5 万行）下优化器因 company_id=1 选择性低未选择新索引（type=ALL 全表扫）；索引已建立但当前不生效，数据量增大后可能被优化器采用，属"保险型"索引。真正的性能提升来自看板 60 秒结果缓存（并发 10 人从 10.6s → 0.2s）。

## 四、索引脚本

以下两条 DDL 已于 2026-08-04 直接在生产库执行，并已补入 `scripts/optimize-board-indexes.sql`（环境重建/迁移时执行该脚本即可复现）：

```sql
-- 看板聚合性能索引（2026-08-04 已执行）
ALTER TABLE `unwarranted_material`
    ADD INDEX `idx_uw_company_ym_plant` (`company_id`, `year_month`, `plant_machine`);

ALTER TABLE `original_record`
    ADD INDEX `idx_or_company_ym` (`company_id`, `year_month`);
```
